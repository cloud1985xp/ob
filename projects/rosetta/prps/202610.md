## 實作 Subject List

類似 /admin/translation_sources 的功能，但另外實作在 /subjects 頁面
主要目的是為了呈現資訊 (不要更動到 /admin/translation_sources)
內容仍是列出 translation_sources ，只是在這邊簡化名稱叫 subject (subject = namespace + property)

需求：
- 只列出 enabled、type = masterdata 的 translation source
- 顯示的資訊：
	- Full Name:  {namespace}.{property}
	- Translation Strategy，依 strategy 顯示不同內容:
		- disabled: 顯示「不翻譯」
		- default 或 rag: 顯示 LLM + strategy_options 選擇的 model 名稱
		- kotoba: 依 strategy_options 選擇的 model 名稱顯示不同內容:
			- mt5: 顯示 MT5 + 使用的 kotoba model (remote_model) 檔案資訊，查找 kotoba_models 是否存在對應的紀錄
				- 若沒特別指定 remote_model，用同 translation source 的 namespace + property 查找
				- 若有指定 remote_model 名稱，用「.」將字串拆開成 namespace + property 查找，例如 `common.name` 即 namespace = common、property = name
			- gemma4: 顯示 GEMMA，並查找 kotoba model 裡 type 為 gemma 的第一筆記錄
			- 若有找到 kotoba model，顯示該筆 model 的 latest_version, ex:
				- MT5 {namespace}.{property}-{latest_version}
				- GEMMA {latest_version}
			- 若沒找到或狀態不是 available，顯示為 MISSING 的 warning label, ex:
				- MT5 {namespace}.{property} `MISSING`
				- GEMMA `MISSING`
			- 用 labels 列出 pattern_strategies (n1、multiple_lines)
	- Glossaries
		- 只顯示數字
		- 數字旁有展開的 icon，點擊後下拉展開(dropdown)，列出 glossary 名稱
- 不需要：
	- Ingestion 資訊
	- Enabled 資訊：會在 subject list 必定是 Enabled
	-  delete 按鈕
	-  view 按鈕，點 Full Name 即可，先一樣連到 admin/translation_sources/:id
- 保留 edit 按鈕 ，先一樣連到 admin/translation_sources/:id/edit，但加一個是開新頁面的連結
- 篩選：
	- 可以用文字欄位篩選，和 /admin/kotoba_models 一樣，用一個文字欄位，對 namespace 做查詢，當查詢文字包含「.」，就拆成對 namespace 和 property 比對
	- 可以用 strategy 選項來篩選: disabled、default、rag、kotoba，可複選
- 依照 namespace, property 排序
- 用 Infinite Scroll 載入更多

整體目標是讓使用者可以清楚直觀地知道，每個使用中的 translation source 的翻譯設定
尤其是當 strategy 是 kotoba 時，有多種 option 的資訊，並結合 kotoba model 的紀錄判斷在 jenkins 上的 remote model 的狀態/版本

請評估上述需求進行實作
若有建議或疑問請提出討論

## 實現 TranslationBatch Checkpoint
TranslationBatch 在執行 TranslatorV2 進行翻譯時
希望可以把進行已完成的 stage 與當下翻譯內容紀錄下來，這樣如果後續失敗重新執行時，可以跳過已完成的 stage

尤其是 model stage 中間，呼叫 provider 完成翻譯後的結果就要存下來
後面失敗就不用重新呼叫 provider 再翻譯一次

這樣應該會需要把 GlossaryCorrection 的動作向外提出變成獨立的一種 CorrectionStage
在 CorrectionStage 裡面決定是否需要執行 GlossaryCorrection 和 NewlinesCorrection (或未來更多種的 stage)
前提是： CorrectionStage 只針對 ModelStage 得到的 translation 做校正

整理目前會套用 Correction 的條件：
- 需要 GlossaryCorrection 的情況：
	- provider = kotoba + model = mt5 而且 TranslationSource 的 glossaries 不為空
	- 進入每筆 string 處理時，若該 string 原文內容沒有 match 的 glossary，則會略過

需要 NewlinesCorrection 的情況
- provider = kotoba + model = mt5 而且 strategy_options 有  Multiple Lines
- 進入每筆 string 處理時，若原文內容沒有換行，則會略過

請評估上述需求是否可行，Correction 的行為是否與現行一致或有衝突
並且規劃實作計畫，若有問題或建議請提出討論
