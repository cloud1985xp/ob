## 實作 TranslatorV2 LLM Provider

實作 TranslatorV2 ModelStage 的 Providers
目前只實作的 mt provider，接下來要實作 LLM provider
請 migrate 舊版的 translator 的整合進 translator v2
原本 translator 就只有呼叫 llm 的行為，將這段移植到 v2 的 LLM Provider 中
讓 TranslatorV2 完全取代 Translator，後者之後就可以

我的認知，使用 LLM provider 翻譯的流程如下：

當 TranslationSource 如果設定成 strategy 為 default or RAG strategy 時
在 model stage 會使用 LLM Provider 來處理翻譯

在進入到 TranslatorV2 時
- 若有 segmentation rule，仍會拆成子 segment 各自處理 translation pipeline 來翻譯，然後將結果合併回原文
- TranslationPipeline 進行時
	- 一樣會經過 Canonical stage，若有符合就使用找到的翻譯
	- 進入 model stage
		- 呼叫 LLM 翻譯
			- 若為 default，不需要附上 glossaries
			- 若為 RAG，會附上 glossaries
		- 不需要做 glossary correction
		- 不需要做 newlines correction
