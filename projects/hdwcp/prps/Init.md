這是一個有關窗簾產品公司的內部平台系統，包括：

- 產品管理：包括產品組成、規格、訂價
- 顧客(經銷商)管理
- 訂單管理
- 銷售統計分析
- 行銷活動
- 使用者登入、權限機制等系統

目前已有現成開發好的程式，位於 ~/projects/hdwcp
當前版本是用 Ruby/Rails 開發的版本

目標是將它改寫並重構成新版本，改用 Elixir + Phoenix + Liveview 來開發
前端改用 esbuild + tailwind4 + daisyUI 
而資料庫結構完全不改變，沿用現有的資料庫

在 Elixir 的開發架構與風格下，以 Context/Domain 來拆分
我目前預計拆分以下的 Context

Sales: 銷售模組，包括訂單的新增編輯動作，訂單流程管理
Shippings: 出貨模組，管理出貨作業
Products: 產品與價格管理
Pricings: 產品計價模組
Marketings: 行銷模組，關於 coupon 券的發行處理作業、行銷活動管理
Settings : 系統管理員(admin) 所有資料基本 CRUD 與設定，使用者帳號管理等

## 規格注意 
這裡提供一些系統規格上特別要注意的地方

### 訂單類型
一筆訂單(order)可以購買多個品項(order_detail)
訂單有四種類型
- 一般商品：即購買窗簾產品的訂單
- 維修單：從過往訂單，轉成維修單，再去設定要維修的品項
- 修改單：從過往訂單，轉成修改單，再去設定要修改的品項，以及要修改的內容項目
- 其他訂單：購買非窗簾產品的訂單，明細品項購買的商品會是其他商品(model)

一張訂單下的品項都會是同一種類型
每個品項：
- 購買數量
- 一個折扣倍率
- 會有牌價與實際售價，用牌價 * 折扣率 計算出實際單價

### 顧客
- 是經銷商制度，所以販售(訂單)對象是銷經商
- 經銷商也會有自己的 user 帳號可以登入系統下單
- 也可以由公司內部的人員幫忙經銷商下單

### 產品
主要產品是窗簾，但也有一些其他商品，如零件、型錄
窗簾產品的結構
- 主分類，主要決定了該窗簾產品是哪一個大分類，不同的分類有不同的產品元件，來組成產品組合
- 組成元件包括：
	- 布類或葉片型號(model)：有些產品類是布料，有些是葉片，但這在系統內沒有顯著差別，都統稱為 model
		- 但 model 也會用來定義非窗簾的其他商品
	- 布料/葉片的顏色代碼：不同的布料/葉片有著不同的顏色代碼可選擇
	- 產品系統(system)：功能的主要特色取決於產品系統，不
	- 操作系統(operation)：代表操控窗簾的模型，例如手動、滑軌、各式電動等等
- 第二組布料或葉片(model2)：有些產品系統需要使用兩組布料(或葉片)，也會有第二組的顏色
- 尺寸：寬度與高度
- 布料或特殊處理選項(category_option): 不同的產品類對上不同的產品組合時，有些會有一些特殊的處理選項，例如可對布料做加工、調整堆疊方式等
- 電動處理選項: 當操作系統是電動型態時，有些會提供相關的選項，依分類(category) + 操作系統(system) 而定

### 極限規格(ModelLimit)
- 每一種產品組合，會有對應的可製作窗簾的極限，
	- 一般組合是 category + system + operation 會有一組規格限制
	- 也有可能更嚴格，當 category + system + operation 再搭配某種 category_option 時，會套用的限制包括
- 限制包括：
	- 寬度與高組合
		- 可能是固定的 寬、高，也可能是階梯式變化的寬高對應限制
	- 材積
		- 也會定義一個材積限制，當下單的商品指定的寬高，經計算後不能超過該材積限制

極限規格也等同於產品的基本組合方式(category+system+operation)，
如果某一個組合沒有定義極限規格，表示這不是合法的產品，等於並沒有販售這樣的產品

### 計價方式與價目表

#### 計價方式
對窗簾產品來說，計價包含商品的基本價格，以及額外項目追加的價格
例如購買某組合 (category+system+operation+model+width+heigth) 的產品，會去對應 model 設定查找價目表(price_table)，得到基本價格

但可以因為 operation、system、category_otpion、other 選項的選擇，而依設定追加額的金額。
追外的金額有可能是依選項有特定的金額
也有可能是再查詢另一張價目表來計算金額

#### 價目表
- 價格可能會隨著是日期區間而調整，基本是一年更新一次，會依訂單訂購的日期，來決定要該哪一個日期區間的價目表
- 價目表一般是長寬而定，所以會定義每個長+寬維度的金額
- 也有可能是只依寬度(或長度)來變化的金額
- 價目表用途
	- 可以是一般定價的產品的價目表
	- 也有可能做為追加項目費用的價目表

訂單所選的 model 有可能是期貨類型的商品
若該窗選擇是期貨，則可能是要改查詢期貨用的價目表
或著(沒有設定期貨價目表)是用現貨價目表來查詢金額，但依該價目表設定另用一個期貨價的公式做追加計算。
