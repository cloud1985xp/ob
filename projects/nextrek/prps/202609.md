# Import with Tag and Contact

我想重新實作 JournalDraft 的 Import 程式
包括以下內容：

一、重構 Import 程式的架構
Import 會需要支援來自多家銀行的檔案格式
但我覺得可以將不同銀行的格式支援方式，設計成一種設定檔的格式
在設定檔中定義欄位的 mapping
若有需要可以再設定欄位的 transformer
這樣要增加支援的銀行，只需要定義新的設定檔
甚至未來使用者可以自己上傳自己的格式，只要自行定義設定檔
(但現階段只支援系統預先定義的設定檔就好，可用 yaml config 定義，未來再用資料表管理)

目前想到設定檔的結構可能包括

- 銀行代號: 可用現有的程式碼的 class 代碼
- 名稱:
- 版本: 方便一個銀行有可能會多個版本的檔案格式
- 欄位對應的定義

二、支援交易的標籤(tag)與對象(contact)資料
新的匯入功能也要能同時匯入交易的 tag 與 contact 資料
contact 只會有一個
tag 則最多可以有5個，在上傳資料中分成五個不同的 column
所以定義檔中也要包含定義如何 mapping 標籤 與 對象

在執行匯入時若 tag 與 contact 是新的值就會同時建立新的資料

所以匯入資料會包括以下欄位：
- 收付日期
- 憑證日期
- 付款金額
- 收款金額
- 附註說明
- 會計項目
- 營業稅
- 手續費
- 發票號碼
- 對象
- 標籤1、標籤2、標籤3、標籤4、標籤5

請先把新版匯入程式架構設計製作完成
