## 優化 Docker Build Image
有兩項目標：
1. 支援 multi platform
2. 改成多階段 build 來優化最後產出的 image size

一、支援 multi platform
希望改用 buildx 指令同時 build x86 與 arm 平台的 image
因為會需要在 container 中安裝許多 native library & gem install
所以想拆出另一個 BaseDockerfile 先 build 好 Base Image
原本的 Dockerfile 就基於 base image 只處理 application 端的 build process，來產生最後的 App Image

二、多階段 build image
為了優化 image build 或出的容量
在 Dockerfile 裡請幫我優化寫法，並且

補充：
目標最後我會用 AWS CodeBuild 啟動 batch job 來 Build 雙平台的 Base Image
App Image 的部分，需要調整原本的 Github Action 成執行 buildx 同時 build 雙版本
這段可以後續討論再進行


另外，因為現在 Dockerfile build image 是基於 Dockerfile.base build 出來的 base image
這個 base image 是透過 Codebuild 執行的
如果專案 repo 的 gemfile 或 Dockerfile.base 有變動，會需要重 build base image
請參考 Codebuild project 裡：
> /Users/aaron.kuo/projects/nextrek-stack/containers/nextrek/build_container.yml:L36-37
它會將該次 build base image 時的 gemfile 和 Dockerfile.base 的 md5 紀錄在 s3 上

請更新 build_image workflow 裡，加上檢查當下 repo 與 s3 上的 md5 是否有差異
若有差異，需要先呼叫 codebuild 專案更新 base image 再 build 自己的 app image
codebuild 的專案名稱為 nk-base-app
