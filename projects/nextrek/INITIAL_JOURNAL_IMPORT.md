# 實作新的交易匯入功能

目前已有交易匯入的功能，但要實作新版本增強功能與優化使用者體驗

前端相關的 css/html/js 等檔案已經準備好，請將它們整合進現有系統中

## 需求說明

### 新版本的前端架構

舊版本的交易頁面是使用傳統 Rails Sprockets 架構，coffeescript + bootstrap 實作的，
目前系統已經逐步轉向使用 esbuild 來管理前端資源，並改用 tailwindcss + daisyUI + ES6，等技術
這次開發的新版本需要將新的交易匯入功能整合進 esbuild 架構中。
前端相關已準備好的資源位於 tmp/journal-import-frontend 目錄下，是一個獨立的前端專案，請將它們整合進現有系統中
- 注意：但不需要移除舊版本的前端資源，因為舊版本的交易匯入功能仍然需要保留
- 注意：不要改動目前新版本已有的 layout，只需整合新的交易匯入功能的部分


在 Controller 的部分，使用 use_v3 即可切換到新版本的 Layout 與前端資源

請參考 Reports::BudgetsController，它已經啟用了新版本的前端架構

### 新版本的「總覽頁面」功能

新版本主要增加了「總覽頁面」的功能，作為新的使用者進入端點主畫面

沿用了舊版本的「交易暫存區」的概念，但重新設計了介面與使用流程
- 交易暫存區指的是使用者上傳交易檔案後，系統暫時存放這些交易資料的地方，這些資料被稱為草稿 (JournalDraft)
- 在舊版本中，交易暫存區的介面較為單純，一次會列出所有草稿資料，使用者需要手動選擇要匯入的交易
- 新版本的匯入功能主要是將匯入的草稿，以「資金帳戶」為單位來分組呈現，換言之每一個資金帳戶會有獨立的交易暫存區
- 資金帳戶暫存區可以被隱藏

總覽頁面則將交易暫存區的功能細分為三個區塊，分別是「最新上傳」、「所有暫存區」與「隱藏的暫存區」

1. 最新上傳：以最近上傳仍未處理的草稿，以資金帳戶為單位來分組呈現
2. 所有暫存區：依所有資金帳戶分組呈現，不論是否有新的草稿，主要是貫徹資金帳戶為單位的概念
3. 隱藏的暫存區：列出所有被使用者隱藏的資金帳戶暫存區，或著說是置底的資金帳戶暫存區，使用者將不常用的資金帳戶暫存區放到這裡

1 與 2 的資金帳戶暫存區點擊後會展該資金帳戶的草稿交易列表，3 則不行

資金帳戶暫存區的項目顯示在三個區塊樣式都不同，請參考前端資源中的設計稿

### 新版本的「草稿列表頁面」功能

草稿列表在舊版本中是使用者的最初進入端點，使用者上傳交易檔案後會直接進入草稿列表頁面

新版本的草稿列表頁面，主要是針對單一資金帳戶的草稿交易進行操作，所以進入列表時草稿就已經依資金帳戶為條件過濾好了

草稿列表的功能基本上沿用舊版本的設計，套用新的前端架構與樣式，並優化使用者體驗與互動，例如動態篩選、分頁、批次選取操作等
請從前端資源中取得相關的 css/html/js 並整合進系統中

建立新的路由來對應新的草稿列表頁面，建議路由格式如下：

總覽畫面
- /journal_drafts：
- JournalDraftsController#index，取代舊版的 JournalDraftsController#index

特定資金帳戶的草稿列表頁面
- /journal_drafts/account/:account_id
- JournalDraftAccountsController#index ，有點像是將舊版的 JournalDraftsController#index 搬來這裡面，並依 account_id 過濾草稿

## 前端資源的整合

請將 tmp/journal-import-frontend 目錄下的前端資源，整合進現有系統的 esbuild 架構中
請參考 tmp/journal-import-frontend/docs/journal-draft.md 中的說明文件來了解各個檔案的用途與功能

若有需要你可以拜訪以下網址來查看前端資源的運作情況，我已經啟動了該前端專案的開發伺服器
- 總覽頁面：http://localhost:5173/accountings/journal_draft_upload
- 草稿列表頁面：http://localhost:5173/accountings/journal_draft

有部分 css/js 的機能是屬於全域性的(例如 plugins)，請將它們整合進符合現有系統架構新版本前端架構的位置
主要端點如 app/javascript/v3.scss 與 app/javascript/v3.js

其他局部 css/js 則放在符合功能模組的位置，請依模組化與功能單一的原則來放置
檔案的命名與內容等請盡量沿用 tmp/journal-import-frontend 目錄下的檔案命名與內容，以減少不必要的改動

再次強調不用去更動新版本(v3) 的既有 layout (app/views/layouts/v3.html) 的 html或樣式結構，
layout 的部分不在這個前端專案的範圍內
