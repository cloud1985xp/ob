# Google Drive Design Image Tool
實作新功能，方便使用者對 Google Drive 上特定目錄的圖片檔進行操作
包括對 Google Drive 進行「檔案上傳」與「檔案下載」
## 背景
由於使用者對 Google Drive 檔案的作業，都會需要同時做多個語言的存取
多個語言包括：en, fr, ko, zh, de, es, jp 
因為各語的圖片檔案名稱會一樣，只是放在不同語言路徑下

例如有個 `myimage.png` 的英文版檔案，位於：
- /aaaa/bbb/ccc/en/ddd/myimage.png

那其他語言，會分別位於：
- /aaaa/bbb/ccc/fr/ddd/myimage.png
- /aaaa/bbb/ccc/ko/ddd/myimage.png
- /aaaa/bbb/ccc/zh/ddd/myimage.png
- /aaaa/bbb/ccc/de/ddd/myimage.png
- /aaaa/bbb/ccc/es/ddd/myimage.png

注意：語言目錄之後的子路徑都會一樣

這讓使用者在做以下動作時，操作繁瑣：
1. 從 google drive 上要下載某一個圖片的六語言版本到本機 ，要到六個不同目錄下找到同一個路徑檔案進行下載
2. 從本機要上傳某個檔案的六語言，分別要在本機找各檔案，再到 drive 上找到各個不同目錄再分別上傳

希望能在本專案增加一個功能，方便使用者快速完成上述操作

## 關鍵規則

### 一、檔案路徑的規則
以 `/aaaa/bbb/ccc/en/ddd/image.png` 為例

其中 `en` 為語言目錄，會有各種語言(en,fr,ko,zh,de,es,jp)

- en 前的 `/aaaa/bbb/ccc` 視為 parent path，或稱 base path
- en 後的 `/dddd/image.png` 為 child path，即目標檔案的路徑，各語言都會一樣

### 二、Google Drive 各語言的 Base Path 可能不同

在本地端時，一個目標檔案，各語言的 base path 會一致
但在 Google Drive 上時，parent path 則有可能會因不同語言而在不同的位置

例如
- en, fr, ko, zh 是用相同的 base directory
- 但 de, es 是用另一個 base directory
ex:
- /path1/directory1/en/folder/png/picture.png
- /path1/directory1/fr/folder/png/picture.png
- /path1/directory1/ko/folder/png/picture.png
- /path1/directory1/zh/folder/png/picture.png
- /path2/directory2/de/folder/png/picture.png
- /path2/directory2/es/folder/png/picture.png

也就是：
- 各語言可以設定各自或共用 parent path(base directory)
- 而語言目錄後的目標檔案路徑 child path 會都一致

註：對 google drive 來說，不同  base path 甚至可以是不同的 drive (shared drive)

## 目標

需實作此功能，提供
- Google Drive 路徑設定
- 檔案打包下載：對應「從 Google Drive 上將對應檔案打包下載」
- 檔案上傳分發：對應「從本地將對應檔案上傳分發」

使用者需要完成 Google Drive 設定，才能使用下載或上傳功能
###  1. Google Drive 路徑設定
無論上傳或下載，都要先設定「各語言在 Google Drive 上的對應 base path」

因為
- 每個語言可以對應各自的 base directory
- 也有可能多個語言對應同個 base directory

所以這裡可以用「新增 drive 資料夾」讓使用者輸入多筆 Google Drive URL item
然後對每筆 URL item 提供用複選(checkbox) 的方式去選擇它要對應的語言有哪些
- 已被選取的語言，在其他 url item 裡就會被 disable 不能再被選取

預設：
- 提供 2 URL item
	- 第一個的語言預先選好 en, fr, ko, zh
	- 第二個的語言預先選好 de, es
	- jp 預設都不選

設定好後先送出，server 端可對所輸入的 url 先做所需要的基本資料 scan，存入 redis 或 memcached
- 針對 Google Drive 路徑設定的 URL items，會以 current user 為 base 紀錄下來，即不同 user 會有不同的 items 的使用設定紀錄
- 而掃描 google drive 上的所需資訊而作的快取 (例如 parent、file list 等等)，可用 global 共享
- 需紀錄最後 scan 的時間
- 需紀錄此次設定所有的「可用語言」是哪些
- 可以重複執行 scan
#### 使用流程

使用者進入設定畫面，出現表單，顯示目前有的 GoogleDrive URL items
- 編輯 items 後按下送出
- 送出後 server 端進行儲存並 scan 對應目錄下的資訊
- 等候 server 處理完成
- 處理完成後顯示成功

### 2. 檔案打包下載功能

#### 目的
讓使用者只要「選擇 Google Drive 一個語言的檔案」，工具自動依同路徑去取得其他需要的語言的檔案，將檔案從 Google Drive 取得並 zip 打包，讓使用者下載回本機
#### 功能需求
從使用者已設定 Google Drive 的 URL 來做為 base path，取得各可用語言下的目錄結構，讓使用者瀏覽其中一個語言下的目錄結構，去找到想要下載的檔案

例如
使用者已設定指向 Google Drive  `/path/somedirectory`  位置的 URL，並完成設定對應到 en, fr, ko, zh, de, es 六個可用語言

預期這個 base directory 目錄下會有該語言的子目錄，也就是
- /path/somedirectory/en
- /path/somedirectory/fr
- /path/somedirectory/ko
- /path/somedirectory/zh
- /path/somedirectory/de
- /path/somedirectory/es

使用者會從其中一個語言的目錄，例如 `/path/somedirectory/en`，瀏覽裡面的檔案結構
例如再進到 `/path/somedirectory/en/png/` 下 ，瀏覽裡面的檔案清單
最終使用者找到並選擇目標檔案，例如 `mypicture.png`

即完整的路徑會是
`/path/somedirectory/en/png/mypicture.png

此時，工具會自動為各可用的語言，依對應的 base path + {語言} + 同樣的 child path 找其他語言的檔案，即：

- /path/somedirectory/en/png/mypicture.png
- /path/somedirectory/fr/png/mypicture.png
- /path/somedirectory/ko/png/mypicture.png
- /path/somedirectory/zh/png/mypicture.png
- /path/somedirectory/de/png/mypicture.png
- /path/somedirectory/es/png/mypicture.png

並且會先檢查這些對應語言檔案是否存在
來提供可下載的語言選項清單給使用者選擇
(若有語言的檔案不存在，即顯示「缺失」不可勾選下載)

執行下載時，會將選擇的語言的檔案，用 Google Drive API 取得檔案內容下載至 server，再打包成 zip 檔，讓使用者下載到本機

下載時，使用者可以選擇打包 zip 的內容模式，會影響 zip 檔案打包的結構
包括：「按照原始路徑」、「省略原始路徑」、「使用語言前綴」

按原始路徑：
打包結構會維持 base directory 下各語言的完整路徑，即解開後
- /en/png/mypicture.png
- /fr/png/mypicture.png
- /ko/png/mypicture.png
- ...

省略原始路徑：
打包結構就只保留 語言目錄 + 檔案，即解開後為
- /en/mypicture.png
- /fr/mypicture.png
- /ko/mypicture.png
- ...

使用語言前綴：
打包結構不需要目錄，只用檔案 + 用語言當前綴，即解開後
- en_mypicture.png
- fr_mypicture.png
- ko_mypicture.png
- ....
#### 使用流程：
- 使用者輸入 base direcoty  並勾選對應的語言，可輸入多組 base directory
	- 按下開始截取目錄結構
- 系統先依輸入的 directory 至 google drive 取得對應 directories 下的目錄結構與檔案清單
	- 正常 base direcoty 下要有各語言的目錄，若有找不到，出現該語言失效的警示，該語言不會出現在最終可以打包下載的語言選項中
- 畫面上出現有效語言的清單，讓使用者選擇挑選一個語言進去找尋圖片檔案
- 在該語言目錄下依目錄結構進行瀏覽檔案，可進入下層目錄，或回到上層
	- 直到選擇要的圖片檔案
		- 系統需紀錄這個檔案對應到 base direcotyr/語言 下的路徑，用同路徑去找其他語言的檔案
- 選擇檔案時，
	- 系用這個檔案的路徑，去查其他語言是否也有對應檔案
	- 更新各語言的可用清單，若有語言沒有檔案，顯示為「缺失」
- 使用者
	- 從可用清單勾選實際想要的語言有哪些
	- 選擇打包模式：
		- 按照原始路徑
		- 省略原始路徑
		- 使用語言前綴
	- 按下「執行打包下載」
- 系統將檔案從 drive 下載下來，放到 新建暫存目錄
	依打包模式將檔案放在對應路徑 or 檔案命名
- 將新建暫存目錄打包成 zip 檔，傳回供讓使用者下載
	- 檔名：package_YYmmddss.zip


### 3. 檔案上傳分發功能

使用者先選擇此次要處理哪些語言，從 en, fr, ko, zh, de, es, jp 來勾選
然後從本機某個本地目錄選取一個語言的檔案

例如 `/mylocal/path/abc/en/xyz/png/file.png`
這意味著其他 en 以外的語言，會位於

- /mylocal/path/abc/fr/xyz/png/file.png
- /mylocal/path/abc/ko/xyz/png/file.png
- /mylocal/path/abc/zh/xyz/png/file.png
- /mylocal/path/abc/de/xyz/png/file.png
- /mylocal/path/abc/es/xyz/png/file.png

(因為本機檔案的 base path 會一致)

首先檢查使用者勾選的語言，是否對應的檔案都存在
若有不存在，則跳出錯誤提示
檢查通過，玩家可按下「上傳按鈕」
即會將對應的語言各檔案
上傳到已設定的各語言 Google Drive base path 對應的 {語言} + child path 上

若以上述的 URL 指向 `/path/somedirectory/` 設定為例
結果會上傳到
- /path/somedirectory/en/xyz/png/file.png
- /path/somedirectory/fr/xyz/png/file.png
- /path/somedirectory/ko/xyz/png/file.png
- /path/somedirectory/zh/xyz/png/file.png
- /path/somedirectory/de/xyz/png/file.png
- /path/somedirectory/es/xyz/png/file.png

若以上述
- en, fr, ko, zh 是用 `path1/directory1/`
- de, es 是用另一個 `path1/directory1/`
為例

上傳結果為
- /path1/directory1/en/xyz/png/file.png
- /path1/directory1/fr/xyz/png/file.png
- /path1/directory1/ko/xyz/png/file.png
- /path1/directory1/zh/xyz/png/file.png
- /path2/directory2/de/xyz/png/file.png
- /path2/directory2/es/xyz/png/file.png

 若目標路徑已有同檔名的檔案，則會複蓋
 -  可將這個行為設為 option，未來可以支援上傳時選擇要不要覆蓋

#### 使用流程
- 進入「檔案上傳分發」
	- 若未完成「Google Drive 路徑設定」顯示提示並導向設定頁
- 使用者先選擇此次上傳，要處理哪些語言
	- 從 en, fr, ko, zh, de, es, jp 來勾選，可一鍵全選
- 使用者選擇檔案
	- 系統檢查使用者本地端是否有對應的語言檔案，若有缺少跳出錯誤提示
	- 若檢查通過，繼續下一步
- 按下上傳
	- 系統將本地檔案上傳到 server 端，server 再依各語言上傳到 Google Drive 上對應的位置
- 顯示處理中的提示，可 print 進度或 log，等候 server 完成
- 完成後顯示成功

## 實作注意與原則
### 紀錄 Google Drive 資料

可以規劃在使用者設定 Google Drive 時，將該 url 對應的 drive 目錄下的資訊先掃描
並轉成適合上述功能查詢、操作的資料結構，存在快取 (memcached or redis) 中
也方便除錯或測試，所以先規劃設計這個資料結構至關重要

### 其他
- 若有非同步的需求，需將工作製作成 background job，並實作 job 的狀態或 log 訊息，用 polling 的方式取得進度，回饋給使用者，可參考現有類似實作
	- app/models/job_state.rb
	- app/controllers/jobs_controller.rb
	- app/javascript/controllers/poll_controller.js
- 有多語言複選 (check boxes) 的欄位，都附上一鍵全選/取消的選項
- 有關前端的操作，例如一鍵全選等動作，請先參考即有的 stimulus controller 用法，盡量重複使用現有的 library

請詳細分析上述需求，並基於現有程式架構擬定計畫
