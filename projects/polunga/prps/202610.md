# 將 Design Drive Setting 可管理化

原本的設計是：每個使用者只有一組設定，紀錄在 redis 中
但如果使用者需要在多組目錄中切換，會需要一直重複設定，操作繁瑣

優化方向是改成使用者可以存多組的設定，可以管理這些設定，並隨時切換要啟用的設定

- 用 database table 來存放 user 的 (DesignDrive) settings
	- 多筆 drive uri 的資訊可 serialize 後用一個欄位存放
	- 可用一個欄位紀錄「目前使用中」
		- 每個使用者最多只能有一筆「使用中」的資料
		- 若沒有「使用中」的設定，進入 upload/download 的頁面都會被導回設定畫面
- 每組設定會有一個代表名稱
	- 在建立時可以自訂名稱，若沒有填寫的話，就用第一個 drive url 的 folder 名稱
- 有一個 settings 列表讓使用者管理自己的，排序依照建立時間由新到舊，可換頁，每頁大小用預設值
	- 可以編輯、刪除 setting
	- 可以將指定的設定「設為使用中」
- 在 upload 與 download 的頁面，原本置於右上方的「顯示當下設定」的區塊，展開後，裡面加上一個 dropdown (可用 tom_select 選單，支援輸入文字篩選)，讓使用者直接切換要用的設定

## DriveSetting 優化「設為使用中」

DriveSetting 的表單，不再自動將送出的 setting 一律為使用中
而是加上「設成使用中」的 checkbox 欄位，讓使用者決定是否要存為使用中：
- 新增 setting 時，預設會勾選
	- 若當下沒有任何其他使用中的 setting，則無法取消勾選
	- 若當下已有其他使用中的 setting，使用者可以取消勾選
		- 在儲存時，就不會將該 settings 設為使用中
- 編輯時
	- 若當下的 setting 為使用中，則不可修改
	- 若當下的 setting 不是使用中，則可以勾選，並在儲存時設為使用中
