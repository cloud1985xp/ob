我想延續目前的架構繼續開發，朝以下的方向

一、拆分 client 端 app
我想讓這個 elixir/phoenix 專案變調整成只負責 server 端運算 + 提供 api / socket 連線，client 端的部分拆出來用另外的技術實作，成為可跨 pc (ex: steam) 、macOS 和 mobile (ios/android) 平台的 app 程式

client 端技術的部分請依遊戲性質、可用資源、可行性等請行評估推薦


二、ingame 演出的實現
ingame 有開發階段和營運階段
開發階段目前顯示有看板模式，但過於單調，我想增加實作更有娛樂性的演出，以下目前的想法

讓畫面上有辦公室的場景，每個團隊小組有辦公桌電腦，有Q版人物在辦公桌工作、忙碌、討論、發言、勞動㚏波的效果

營運階段也可以延用這個畫面，搭配原本計畫的營運 dashboard，在儀表板上出現伺服器和遊戲營運的各向指標追蹤，搭配辦公室場景的演出 

這部分請詳細評估、提出建議，
若有不同的想法也請大膽提出
且可以先從開發階段的規劃實作開始，營運階段可以拆分成後續的任務

三、素材與遊戲資料 (masterdata)
實作過程中我們甚至可以透過 MCP 整合 blender 或 comfyui 來協助製作素材
並將遊戲設定資料(masterdata)、參數設計成 csv 或 json 來管理
由於都用 masterdata 控制，數值的公平性、合理性可以暫時先忽略，方便測試驗收，未來再詳細考究怎麼調整數值

必須確保這些 assets 與 遊戲設定資料 (masterdata) 未來是可以持續營運維護更新的，類似服務型遊戲的方式經營

四、遊戲內容整體
遊戲預期會有劇情故事模式，以平可能會有角色抽卡轉蛋
故事就是簡單角色立繪、差分加上場景圖片與文字對白、播放語音，先不考慮複雜的動畫

可以仍先著重在遊戲的核心 ingame 上
只是先討論未來可能的全貌，在評估規劃上會需要先考量
