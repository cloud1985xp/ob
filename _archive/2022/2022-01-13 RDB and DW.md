嗨，大家如果對於 資料庫系統、SQL 、BigQuery 或 Workshop 任何方面有疑問，
都歡迎在這裡提問，工程師們會盡量解答

在這裡先回應一下昨天 meet 頻道中 @stone.chang 提的問題(也是大部分各位昨天所遇到的權限問題)
Stone 的問題大概意思是：我在 BigQuery 下的 query 是 SELECT 指令，為何出現的問題卻是沒有  job create 的權限呢

這個問題的水很深，我盡量簡單說明

因為這邊有一些朋友來自 ISHIN，可能不少人曾有使用 Sequel Pro 連到 ISHIN 的 MySQL database 的使用經驗
ISHIN 和 Mikoto 其實都有使用 MySQL 這套 database 系統
MySQL 是一種的關聯式資料庫系統 (即昨天 Akash 所介紹 Relational Database 有提到，以下簡稱 RDB)

但 BigQuery (以下簡稱 BQ) 則不是，BQ 是一種 Big Data Warehouse，(Date warehouse 中文我們通常叫資料倉儲)
Relational Database 與 Data Warehouse 在應用的情境是不太一樣的 (雖然 Query 的使用是很像的)


Relational Database

RDB 主要是業務上的使用，簡單說目的就是用來建置想要提供給用戶(End User)的服務，會依應用邏輯來設計&使用，
例如是轉蛋的功能，去設計它的卡機資料、轉蛋紀錄的資料庫，又或者是電商服務，去產設各種產品、價格表、訂單等使用
所以 RDB 主要目的是快速穩定地去依業務邏輯讀取或寫入某部分資料，完成這個商業上的需求(一堆人逛商店、下訂單、搶票、抽卡等)
它的主要應用情境比較會是 頻繁，資料量小，且需要 即時 (<1second)完成得到結果的


Data Warehouse

資料倉儲則設計上就是為了 分析統計 為目的，所以它是著重在處理大量資料的查詢與統計
例如計算每日的 KPI 報表，過去30天的玩家分群、過去三個月的玩家留存
它的使用情況則是 低頻率/批次(例如每分鐘/每小時/每天/每月)，但 資料量大 ，而且需要較 長時間處理計算的工作，像是加總、平均、甚至一些複雜的迴歸計算

了解上面講的兩種不同特性後

你在 Sequel Pro(對 MySQL) 下 query 查詢的時候，它理應上是要即時回應的
就像我們的 Server 在處理玩家的行為時，其實是不斷的在跟 RDB 溝通，所以處理時間要很快
倘若你下了一個需要處理很多資料的複雜查詢時，你的 Sequel Pro 是會卡在那邊等候(然後你不能做其他事情)
這個情況我們會用「同步」來形容，就是從你下指令到系統回應結果給你，是在同一個時間線上(我想不到更好的形容)，你必須等 ~

其實換言之 RDB 主要就不是來給你執行一個會需要這麼久時間的查詢，不是不行，只是不擅長

好了，那 BigQuery (Data Warehouse) 呢
前面說它被設計出來的目的就是處理大量資料計算的，所以它追求的並不是要多即時的回覆
所以你在 BQ 下完查詢，是不會停在那裡等候的，你不用等 ，可以去做其他的事，這種我們就會稱為「非同步」的處理
而這個非同步呢，其實就是另產生一個 job，先存下來要做的事，系統背後會另外執行程式默默地去完成它，再把結果傳回來給你

嗯～就像你在 Jira 上開一個 ticket，開完以後等有人撿去做，做好了他再通知你完成

所以回到一開始 Stone 的問題，若要使用 BigQuery Editor 上執行查詢，你還必須要有產生這個 Job 的權限
(抱歉，沒有事先幫大家設定好 :pray:)

所以白話一點，就是你沒有開 ticket 的權限
